# Comparateur local synthétique

Exécuter depuis ce dossier : `python3 runner.py --output /chemin/nouveau.jsonl`. Dix cas figés issus de `../integrated-t_dab1958b/fixtures.py`, trois bras, ordre aléatoire par cas et répétition (graine 0). Aucun réseau, aucune donnée réelle et aucun code généré exécuté. Les bras défaut et configurable utilisent un générateur fictif ; les échecs exacts ne mesurent pas la qualité d'un modèle. Le défaut `synthetic-default/none` est une configuration de référence de test, pas le défaut observé d'OMP. La fonction `decide` est injectable dans l'API `run` ; le décideur inclus est simulé et utilise la même route.

Pour activer le vrai classifieur local : `python runner.py --weights /chemin/du/snapshot --output /chemin/nouveau.jsonl`, avec numpy, tokenizers et onnxruntime installés et le wrapper officiel conservé dans `../pilot-t_f21a25b3/s1d1_upstream.py`. Il classe uniquement le premier prompt une fois par parcours, et la route reste figée pour les tours suivants. La politique expérimentale est explicitement constante : toutes sorties vers `synthetic-default/none`, sans seuil inventé ; elle ne démontre aucun gain de routage. Sans poids/runtime utilisables, le bras est indisponible avec raison ; il n'est jamais remplacé par une simulation. La génération s1d1 est simulée même quand le classifieur est réel : provenance mixte.

Les familles code et sous-agents sont non exécutables sans isolation et instrumentation des permissions ; diagnostic est exécuté mais non évalué sans revue humaine aveugle. Simple et conversation sont évalués par exactitude. Les erreurs d'exécution et les cas non évalués restent distincts. Chaque ligne indique les états, temps monotones, choix, provenance des composants et usage inconnu (`null`) ; les coûts/tarifs inconnus ne valent pas zéro. Le chargement initial du modèle est hors des temps par parcours. `python3 runner.py --summary /chemin/reçus.jsonl` affiche les dénominateurs et latences disponibles par split, famille, bras et provenance sans revendiquer de coût ou d'économie. Les réponses ne sont pas conservées : une revue diagnostique exige un canal de conservation adapté, explicitement autorisé.

L'adaptateur aval doit relier un défaut modèle/effort réellement observé, les générateurs et le décideur local, maintenir une session hôte isolée par bras et cas, rendre l'effort appliqué et les catégories de consommation observables, et établir sandbox, revue humaine et permissions sous-agents avant d'élargir les oracles. Ce pilote ne prouve ni intégration OMP, ni qualité, ni facture. Aucune dépense ni transfert privé n'est autorisé ; un benchmark payant exige un budget et une autorisation explicites.
