# Gateway contract

`python3 omr.py serve --config PATH --port PORT` binds loopback. Requests to `/v1/chat/completions`, `/v1/responses` and `/v1/messages` use virtual model `open-model-router`; only a route explicitly declaring that exact protocol may serve it. Requests and responses retain protocol fields and upstream response identity; only the outbound model and explicitly configured supported effort are changed. No implicit fallback or protocol translation.

JSON config declares `routes` (URL including endpoint path, upstream model, protocol, optional effort), `default_route`, and `decision` (`fixed`, `s1d1`, or `command`). Forwarding received credentials is opt-in for the exact configured route endpoint; presets have none. No secrets in versioned configuration. Command decision requires explicit public-prompt consent, bounded JSON stdin/stdout and deadline. s1d1 loads local weights only after verifying the adjacent identity manifest. Decisions use the first user prompt; session continuity requires explicit `X-OMR-Session`, never a content hash. JSONL receipts contain metadata and usage only, no prompt or credentials. SSE events are forwarded after bounded inspection; recognized provider errors are replaced with a generic event, with cancellation and deadlines propagated upstream.

Tests use loopback synthetic providers only; actual provider capabilities and host integrations require independent validation. No real generation during this pass.

POST negotiation sets `Accept: text/event-stream` when the request streams, otherwise `Accept: application/json`. Only the pinned native streaming route may accept a truly absent Content-Type: it validates complete SSE frames before forwarding, beginning with response.created and ending with response.completed and clean framing. Explicit empty or incorrect MIME remains rejected. Headerless validation checks the supported pinned Codex SDK event envelope and consumed fields, and rejects non-null output-item errors; unsupported event types fail closed rather than disappear. Unrelated extensions and tool argument text on supported events are preserved. Downstream MIME remains absent, and failures after headers become sanitized stream errors. Native Codex 0.162.1 probes require `--disable enable_request_compression` and an explicit per-conversation UUID via `X-OMR-Session` when the client does not provide `session_id`; these prerequisites alone do not establish a working Mac integration.

## Runtime limits and observability

`timeout_seconds` bounds each request including upstream headers and body (default 120); disconnect closes the upstream socket even while waiting for headers. JSON requests are bounded to 1 MiB and responses to 16 MiB. Streaming forwards complete bounded events, never waits for the full response. The gateway binds only loopback and rejects browser Origin requests; it is for trusted local clients, not a public server. Credentials are dropped unless `forward_auth: true` is explicitly set on a TLS route (loopback is allowed for tests). No redirect or automatic retry occurs.

Routes may declare `protocol` as one name or a list. A URL can be the exact protocol endpoint or its `/v1` base. Claude's `?beta=true` is preserved. A configured effort overwrites the host effort explicitly; `none` maps to disabled thinking for Messages. The receipt distinguishes transmitted effort, provider acknowledgement and unproven application.

`receipts` names a JSONL metadata-only file. Each reply exposes X-OMR-Route, X-OMR-Effort, X-OMR-Decision-Ms and X-OMR-Request. Sessions use explicit UUIDs and retain a route for the lifetime of the server; a bounded session table rejects new sessions when full rather than silently reclassifying. An absent session header gives a stateless request only outside native mode. Native POST requires a UUID in `X-OMR-Session` or `session_id`; both must agree if present, and duplicates are rejected. The command decider receives only the bounded first user prompt, never tool results or system messages. It requires `public_prompts: true`; unknown decision results are refused, without fallback.

Receipts accept only bounded numeric token fields, enumerated effort values and a model identity matching the configured concrete model. Unknown upstream model strings are omitted and flagged, never stored. Successful non-error response content reaches its requesting client. The gateway requires the protocol's terminal SSE event and checks HTTP framing; EOF alone is not a completed inference. All upstream HTTP errors use a constant JSON body without reading the upstream body; 4xx/5xx statuses are preserved and redirects become 502 without Location. Recognized SSE error events are replaced with a constant error event. An absolute deadline also bounds request headers and body ingestion, including clients sending one byte at a time.


## Codex native slice — implemented and tested offline only

This section describes the offline-tested implementation, not evidence of a live integration. The only allowed Codex upstream base is `https://chatgpt.com/backend-api/codex` over verified TLS on port 443, without credentials in the URL, query, fragment, or redirects. The local gateway may expose only `GET /backend-api/codex/models` and `POST /backend-api/codex/responses`; it must reject arbitrary versions, endpoints and mixed concrete models.

Both routes require an independently generated ephemeral gateway key supplied explicitly through an environment variable and compared in constant time to `X-OMR-Gateway-Key`. Missing or incorrect keys fail closed before any upstream request. The gateway must never forward, echo or log that key, and must never read a Codex credential file. Codex native bearer and account identity are passed only in memory to the pinned upstream. Preserve documented native protocol headers including `originator` and `X-OpenAI-Fedramp`, but remove all gateway headers, cookies and hop-by-hop headers including headers named by `Connection`; requests naming Authorization or chatgpt-account-id in Connection are rejected locally. Never log request headers or credentials. Local listener must remain loopback only.

The model catalog must come from the authenticated upstream, isolated across accounts; a virtual `open-model-router` entry may only inherit metadata from the configured concrete model actually present in that catalog. Preserve that entry's real default and supported efforts; reject absent, inconsistent or unsupported capabilities rather than synthesizing them. All Codex routes must use the same concrete model so a single virtual alias cannot misrepresent capabilities. Response generation must reject unproven catalog or effort configurations, preserve the established streaming, cancellation and deadline guarantees, and never retry or follow redirects.

Validation is offline only: use mocked HTTP transports to a synthetic loopback upstream (not a TLS test) that leaves production URL validation intact. Exercise malicious endpoints, header filtering and absence from logs, no redirects, actual catalog metadata, missing gateway key, account isolation, SSE and cancellation. No real client credential or provider call is authorized by this specification. Previous evidence hashes and historical results remain historical; a passing mock test does not qualify a real Codex integration.

For native mode every route must use the exact base `https://chatgpt.com/backend-api/codex`, protocol `responses`, and the same concrete model. Set `gateway_key_env` to the name of an environment variable containing at least 32 characters before startup. The native client supplies that value in `X-OMR-Gateway-Key`, plus its synthetic or authorized bearer and `chatgpt-account-id`. GET models first for each bearer/account pair; only then can POST responses use efforts from that observed catalog. The account-scoped capability and session tables are in-memory and bounded by `max_sessions`; restart clears them. Offline transport tests replace HTTPSConnection with a loopback synthetic provider; no real credentials or provider calls were used.
