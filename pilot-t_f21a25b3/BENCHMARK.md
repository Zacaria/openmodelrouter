# Local benchmark runner (prototype)

`python3 benchmark.py config.json cases.json output.jsonl` runs each case and repetition separately through the three configured arms. Each arm is a trusted local executable accepting a JSON request on stdin and returning JSON with `answer`, `usage`, `rates`, `decision_cost`, and `retry_cost`. The s1d1 arm must actually invoke the pinned s1d1 classifier; naming a simulated command `s1d1` is not evidence of inference. Exact-answer grading is predefined per case. Errors are recorded per attempt and do not abort remaining runs. Output is created exclusively and never overwritten.

Each receipt records arm, case, split, family, repetition, provenance, elapsed wall time, success, usage and rates. Provenance is explicitly configured as `simulated` or `real-local`; it is not independently verified by this runner. Never use a real-local label for a simulated generator. Runs are sequential, with no cache controlled by this runner; backend caches and model state must be documented separately. Commands are trusted code, not sandboxed. Do not pass private data or invoke paid/remote services without separate authorization.

`compare.py` reports observed usage per category and routed equivalent value; when `baseline_rates` are present it also reports the same observed volume repriced at baseline rates. This estimate is not an executed baseline or a subscription invoice. Failed attempts with unknown usage remain failures with unknown costs; they are never counted as zero-cost successes. Development and validation cases must be disjoint and validation must not tune the router.
