# MVP oh-my-pi — subscriptions and guided setup

Owner decision: Desktop conversation of 6 November 2026. Execute in this conversation, without Kanban dispatch or implementation delegation. Existing tickets may only be updated for work completed here. The earlier all-platform goal remains a separate acceptance; this MVP targets macOS Apple Silicon first.

## User journey

Install the publicly distributed macOS app, connect Codex and a multi-model Nous Portal subscription, configure Jev with its API key, then work through oh-my-pi using OMR automatic profiles or an explicit direct model. Run a real multi-turn task with a tool round trip, cancellation and recovery; inspect the exact corresponding receipts. Never substitute a loopback fixture for subscription access.

Anthropic's current authentication policy does not permit third-party applications to intermediate Claude Pro/Max credentials. Do not expose that subscription as an OMR login. Claude models accessible through a separately authorized API or Nous subscription are distinct.

## Integrated onboarding

Use React Joyride, compatible with the existing React version, for a replayable contextual tour. The tour must use the real provider, decision, client-connection and inspector screens, not mock screens. It may navigate and explain controls but must never save credentials, approve context disclosure, launch inference, import a native credential store, or mark setup verified. Progress persistence contains only the step and open/closed state; skipping/restarting the tour does not modify provider configuration. Missing targets pause the tour with a visible retry rather than silently skipping a required step. Keep the existing configuration wizard available during implementation; the tour replaces the need for an external first-use guide, not real connection controls.

## Access and implementation

Reuse pinned pi-ai adapters, existing OS credential storage, gateway/session controls, native client launcher, and Jev's SystemOne decoder. Codex is not routable merely because its native-strategies screen exists. Nous Portal's subscription inference endpoint and legacy API-credit endpoint are separate products; do not conflate credentials or claim that an API key automatically uses subscription quota. Reuse an officially supported flow; no copying native stores, new spending or privacy-setting changes.

The existing corresponding-source kit must include the new Python subscription/Portal modules and the TypeScript subscription adapter, so the delivered engine remains rebuildable.

Native qualification must keep the real platform HOME. On macOS 14+, an explicit `OMR_DESKTOP_PROFILE` canonical non-nil UUID selects a private engine directory under `profiles/<UUID>`, a separate keyring service (including benchmark credentials), and a distinct WKWebView data store. Validate the selector before any profile access, reject symlinks or unsafe directory ownership/permissions, and never fall back to normal-profile credentials. Without the selector, preserve the existing path/service and normal Hermes discovery. Private profiles do not register the global autostart plugin. Unsupported private-profile launches must fail closed before constructing a WebView. This is scoped application-data isolation, not another macOS account or automatic Keychain unlock.

## Delivery acceptance

Private windows must be removed from Tauri's automatic window list and created explicitly with `WebviewWindowBuilder::data_store_identifier` before `build`. The locked runtime does not forward the similarly named `WindowConfig` field. Preserve the normal automatic window path without a private selector, and verify distinct persistent stores on macOS before acceptance.

Review repair requirements: accept and validate the pinned Codex SDK's identity metadata without exposing it to the WebView; protect the Hermes connector with a per-start private bearer before it opens a listener; return validated Nous device instructions and cancellation through private IPC; and let an expired external gateway request await native-vault refresh independently of the WebView. Refresh must persist rotated grants before use, never retry inference, respect request cancellation/deadlines, and coalesce concurrent requests. The old candidate is rejected and must not be installed or published.

SDK dispatch must preserve the configured provider base independently of the client protocol path. The Codex subscription base remains exactly `https://chatgpt.com/backend-api/codex`; it is not an OpenAI-compatible HTTP `/v1` base. Send the validated base and requested protocol to the existing private pi-ai adapter without composing or validating a direct-HTTP endpoint for that transport. Keep direct HTTP endpoint restrictions and fixed-origin subscription validation unchanged. Exercise Chat and Responses through the authenticated gateway, not only `Runtime.select`, before native requalification.

Coalescing is per account: one slow refresh or failed vault commit must not delay another account's refresh or give it the first account's error. Retain a rotated grant until its native commit even if its HTTP waiters cancel.

Bind each refresh job to its source grant. Replacing or removing credentials invalidates the previous job and its waiters, even if a reconnect returns the same credential bytes. A late result must neither overwrite a newer login nor restore a disconnected account. Only the native vault owner may commit; cover its actual private IPC/persistence path with an isolated mock vault, not only a simulated Python commit.

Login grants stay in the existing CodexLogin transaction until its native persistence/sync and sidecar commit succeed; cancellation clears that transaction. The native retry map retains only refresh rotations, never uncommitted login credentials. Failed login storage must not discard the existing account's refresh. Cover failed storage followed by snapshot, cancellation, successful retry, rotation and a later login status poll.

After a failed subscription status poll, show the current error instead of stale browser instructions or a stale device code. Keep the pending transaction and its cancellation available. A successful retry clears that poll error without dismissing an independent browser-opening failure. Describe a vault failure as unverified persistence, not proof that nothing was written: the native write can succeed before its readback fails. Exercise waiting → rejected poll → successful recovery through the built UI with synthetic IPC.

After an explicit Codex or Nous login request, open the browser once when current validated device instructions arrive, including instructions delivered by a later status poll. Use the existing native `open_subscription_login` command with only the connection identifier; never open a renderer-supplied URL. Status polling and mounting an existing pending login must not open new tabs. Cancellation and retired views invalidate late responses. Keep the displayed address/code, explicit browser-reopen button and cancellation as fallbacks, show browser-opening errors without automatic retries, and clear that error on a successful manual retry. The Brave replay covers immediate/delayed instructions, repeated polls, remount, browser failure/retry and a delayed pre-cancel response; OS browser launching remains a separate native qualification.

The same replay controls response order for a status request begun during login and an older browser failure delivered after a successful manual retry. Both must leave the newer UI state intact. It also covers navigation away during a pending login and delayed Codex instructions; all authentication and opener responses remain synthetic.

Action results use the existing Radix Toast primitive in a body portal fixed to the viewport, not an inline banner above a scrolled form. Successes expire after six seconds and errors after ten, paused during hover/focus; source resolution can retract its own error sooner. Show the newest three notices on tall windows, the newest one below 600px height, so a new action result is visible immediately even when earlier errors fill the stack. Retain older overflow with a visible count and pause its timers while hidden; it returns with a full duration instead of being silently evicted. Unchanged polling errors do not re-enqueue; resolving or retiring their source retracts the matching toast by identity, without deleting another action’s notice. Preserve both distinct global and save errors, suppressing only the duplicate of the same message. Keep contextual field errors, receipt history, progress and device instructions in their original panels after toast expiry; never toast device codes, login addresses or secret values. The deterministic browser replay covers scrolled success/error, both themes, short windows, retained overflow, keyboard dismissal, timer pause, close controls above a modal, bounded error lifetime, immediate visibility under error saturation, and resolution of a browser-opening error by a successful manual retry. Synthetic UI results do not qualify native WebKit or provider inference.

Build and test the exact candidate, obtain required independent review, produce a signed/notarized macOS package using the existing release path, install and exercise its real reference journey, publish through the existing landing, and verify downloaded identity. Report source tests, mocked upstreams, native execution, actual subscription inference and public availability independently.
