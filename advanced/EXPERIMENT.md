# Protocole des essais synthétiques

Quatre bras séquentiels, mêmes instructions/specification et un thread frais par bras : maintien, changement du modèle de tour, compaction native puis changement, délégation native bornée. Le premier tour appelle uniquement `read_fixture`, un outil de données constant explicitement autorisé. La valeur blue-otter-73 n'est pas incluse dans le prompt utilisateur du premier tour ; elle doit être rappelée depuis le résultat d'outil.

Avant les prochains replays, critères fixés : résultat initial LIGHT, résultat final HEAVY + blue-otter-73 + préfixe RAPPORT:, exactement un appel de l'outil autorisé au premier tour et aucun nouveau résultat d'outil dans la réponse de rappel. Compaction : item natif terminé et tour réussi. Délégation : exactement un enfant natif démarré puis terminé, résultat intégré au tour parent. La répétition doit conserver ses échecs.

Comparer durée bout-en-bout des actions (seed inclus), compteurs natifs parent et enfants séparés, cache, raisonnement et coût auxiliaire disponible. Ne pas additionner les snapshots cumulatifs, ni assimiler `last` à un total de tour lorsqu'il contient plusieurs appels. Si une compaction distante ne fournit pas ses tokens d'entrée/sortie, son coût reste **inconnu** et le coût total du bras aussi. Les compteurs de contexte d'après-compaction ne sont pas des tokens facturés. Les métriques de chaque thread enfant s'ajoutent uniquement lorsque le fournisseur ne les inclut pas déjà dans celles du parent ; ici les événements ont des threads distincts, et le rapport les expose séparément avant total observable.

Les essais 1–2 sont des sondes de qualification, pas des répétitions comparables : absence de rollout ephemeral, puis helper code-mode non monté. Le premier jeu pleinement exécuté est `codex-native-3`. Les prochains replays reprennent les quatre bras ; ils ne constituent pas un benchmark de qualité généralisable (un seul micro-projet, ordre fixe, cache observable mais non neutralisé).

Annulation : démarrer `CodexStrategies.turn` synchrone sur un thread de travail, attendre un item natif via l'observateur, appeler `CodexStrategies.cancel` depuis le thread de contrôle sur le même `StdioRPC`. Exiger l'ack sans timeout, l'échec explicite du tour actif avec status interrupted puis une reprise réussie ; le calcul fournisseur n'est pas instrumenté. Erreur contrôlée : model non annoncé, refus natif sans fallback automatique, puis reprise sur modèle annoncé. Autorisations : aucune approbation automatique ; seul read_fixture sur les threads synthétiques créés dans ce processus et avec arguments exactement vides possède un résultat autorisé.
